Inverse design · hexagonal parent lattice · branch feat/inverse-design

Given a transmission spectrum, which material made it?

Today our Shazam lookup answers with the closest material already in the catalogue. This project replaces that with a model that proposes tight-binding hosts from a continuous family, says how many impurities each would need, gives every answer a probability, and then checks each answer by simulating it.

This page walks through the whole process with live figures. Every figure has a numbered caption that says what it shows and how to read it. The spectra in Figure 2 are real catalogue data; numbers marked "illustrative" are for explanation only.

1 · The input

What a transmission spectrum tells us

A ribbon connected to two leads transmits electrons through a number of open channels at each energy. A clean ribbon gives a staircase: each step is a new band opening up. Impurities scatter electrons, so the disordered spectrum sits below the staircase and becomes ragged. The shape of the staircase is a fingerprint of the host lattice; how far the spectrum falls below it carries the impurity density.

2 · The host space

One parent lattice that contains many materials

To let the model say "a host like hBN, but with a smaller gap", the hosts must live in a continuous space with physical axes. We use a hexagonal parent lattice with six sites per cell, in three types:

  • C, one site at each hexagon centre. Alone, these form the triangular lattice.
  • H, the two honeycomb sites A and B. Alone, these form graphene, silicene, germanene, and hBN when A and B have different energies.
  • K, three sites at the midpoints of the honeycomb bonds. Alone, these form the kagome lattice.

Each type can be switched on or off, giving 7 patterns. Hoppings are identified by the pair of site types and their distance. Inactive types have no sites at all, so switching a type off is exact rather than approximate.

3 · The prior

Which hosts the model is trained on

The training set is drawn at random from a prior: a recipe that says how likely each pattern, energy and hopping is before we see any spectrum. Several choices in it are deliberate:

  • The 7 patterns are equally likely, so the model sees mixed hosts as often as simple ones.
  • Half of the honeycomb hosts get Δ = 0 exactly, and half of single-type hosts get on-site energy 0 exactly. This puts graphene-like and kagome-like materials on high-probability points instead of on a line of zero width.
  • Optional hoppings are either exactly off or at least 0.05 (0.03 for tAA), so "off" and "almost off" are not confused.
  • Mixed hosts must be connected: the active types are linked by inter-type hoppings, so no part of the ribbon floats free.
4 · The builder gate

Proving the parent reproduces today's builders

Before generating any data, the new builder had to reproduce the existing graphene, hBN, triangular and kagome builders exactly. If it did not, every training example would describe slightly different physics from the catalogue the model is later tested on.

5 · Training data

From one random draw to one training example

Each training example is one host from the prior, one impurity count and one disorder seed, simulated into a 416-channel spectrum. Draws that the spectrum could not possibly identify are rejected and redrawn. The checks run cheapest first, so a rejected draw usually costs milliseconds instead of a minute.

6 · The generative model

Learning the probability of a host given a spectrum

A regression model would return one best guess. A spectrum can be explained by several different hosts, so we want the whole distribution p(host, edge, width, density | spectrum). The model splits that into a discrete part (which pattern, which edge, which switches) and a continuous part (the energies and hoppings), because the two need different tools.

7 · From samples to answers

Five candidates, each checked by simulation

The 1,000 samples are grouped by edge and pattern, then clustered. Each cluster holding at least 20 samples is a candidate, represented by its medoid (the real sample nearest the cluster centre). Its model probability is the share of samples in its cluster. The top five are returned.

Each realistic candidate is then simulated on 50 fresh disorder seeds that were never used in training. It "recreates" the target when the target's misfit to the median simulated spectrum is no worse than the 95th percentile of the simulations' own misfits. If it fails, a local optimiser tunes its parameters with a budget of 200 simulations and then re-checks on 50 new seeds. Finally the model probability is combined with how well the simulations fit:

piupdated = pi Li1/κ ÷ ( Σj pj Lj1/κ + p0 L01/κ )

Here Li is the likelihood of the target under candidate i's simulations, and p0 is the probability of everything not returned, paired with a background likelihood L0. Because of that background term, when every candidate fits badly all the updated probabilities fall toward zero instead of being forced to add up to 100%.

What building it taught us

Two builders can store the same atom in different cells.

A ribbon repeats along its length, so an atom can be listed in any copy of the repeating cell. The kagome builder placed some sites up to nine cells away from where the parent put them. The clean spectra still agreed only to 1e-5, not 1e-10, until the parent folded every site into one standard strip.

Counting neighbours needs care on a periodic ribbon.

On the zigzag edge the ribbon period is exactly twice the kagome spacing, so one kagome site bonds to the same partner twice: once in its own cell and once in the next. Counting partners undercounts; counting bonds gives the right four.

Units were checked against the catalogue, not assumed.

A graphene ribbon built by the new code and by the old catalogue pipeline gives identical spectra, clean and disordered. A slip here would have made every training example wrong.

A multi-day job must fail loudly.

Review found that the first version of the generator could report an error and then never exit, and could take hours to notice a crashed worker. Both are fixed and tested: a failure now stops the run within seconds.
